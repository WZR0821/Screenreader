# 读屏 1.3.1（29）

日期：2026-11-11。开发者：Jerry Wong。最低 iOS 18.0。

本版包含两部分：一是此前以 1.4.0（28）测试包形式做出的长文、报错、思考强度和流式显示改进；二是本轮的设置交互修正和界面调整。1.4.0 测试包没有正式发布，版本号按要求定为 1.3.1，构建号继续递增为 29。

> 如果手机上装过 1.4.0（28）测试包，直接用 1.3.1（29）覆盖安装即可：版本号变小，但构建号更大，设置和记录都会保留。

## 本轮修正

### 设置改动不再悄悄丢失

1.3.0 的“翻译偏好”和“缓存与记录”需要点右上角“保存”。不点保存就返回，改动会被直接丢掉，也没有任何提示。“外观与阅读”却是即选即生效，几页的行为不一致。

1.3.1 统一为：

- **翻译偏好、缓存与记录**：和外观页一样，选完立即生效，去掉了“保存”按钮。术语表在收起键盘或离开本页时自动保存，超过 4,000 字时字数变红，并提示无法保存。
- **API 设置、模式提示词**：涉及密钥和长文本，仍保留“保存”按钮，但改为：
  - 没有改动时，“保存”是灰的，不能点。
  - 有改动时，左上角的返回按钮换成“取消”，同时禁用右滑返回。点“取消”会询问：保存、放弃更改，或继续编辑。
- “测试连接”使用本页当前填写的内容。连接成功后，有未保存的改动时提示“保存后生效”，没有改动时只提示“连接成功”。

### 删除记录前先确认

以下操作会删掉已保存的翻译记录，现在都会先弹出确认，并写明要删多少条：

- 关闭“保存翻译记录”（已有记录时）。
- 把“保留条数”调到比现有记录更少。
- 清空翻译记录（原来就有确认，文案改为写明条数）。

关闭“复用近期译文与识字”时，会立即清掉内存里的缓存，并刷新缓存统计。

### 类苹果风格的界面调整

- **设置首页**：改成系统“设置”App 的样式，左侧彩色图标，右侧显示当前值，例如“英语 → 简体中文”“DeepSeek”“30 条”“已关闭”。原来每行下面的说明小字去掉了。
- **外观与阅读**：两项合并到一组，右侧分别显示当前字体，以及“深浅色 · 主题色”。
- **API 设置**：“模型”一行原来整行显示成主题色，像一个链接。现在和系统列表一致：标题用正文颜色，模型名用次要灰色，右侧是浅灰箭头。选“自定义 API”时，原来“模型”行下面还有一行没有标题的输入框，看起来像重复显示的模型名；现在改为“模型 ID”一行（右侧可直接输入），下面一行是“从可用模型中选择”。
- **选择模型列表**：模型名原来是主题色，现在改用正文颜色，说明文字为灰色，只有当前选中项的对勾用主题色。
- **译文核对按钮**：原来每段右侧都有“核对”文字按钮，短段落多时整页像一列按钮，而且按钮和正文不在同一行高度。现在改为一个浅灰色小图标，和该段第一行文字对齐；核对过的段落显示主题色对勾。点按区域仍是 44×44，读屏软件仍读作“核对第 N 段译文”。表格行的图标改为竖直居中。
- **报错横幅**：原来是红字配浅红底，长报错不好读。现在正文用常规文字颜色，只保留红色警告图标和浅红底色。
- **圆角**：卡片、图片、预览和主题色块统一改用系统的连续圆角，去掉卡片外框细线。
- 结果页的“更多”按钮改为 `ellipsis.circle`；复制成功时图标有替换动画。

### 其他

- 修正了 1.4.0 新增的 `Release140Tests.swift`：它只能在 Swift 包里编译，Xcode 的测试 target 会因为找不到 `ScreenTranslateCore` 模块而编译失败。1.4.0 当时没有编译测试 target，所以没发现。现在和其他测试文件一样，按环境选择导入的模块。
- 界面测试同步更新：去掉了对已删除“保存”按钮的点按，改为检查改动立即生效，以及 API 页无改动时“保存”不可点。

## 1.4.0 测试包中的改进（并入本版）

### 报错显示服务商原话

API 请求失败时，除了原来的 HTTP 状态说明，还会显示服务商返回的错误信息，例如“上下文过长”“模型不存在”“额度用完”。

- 只读取 JSON 里的 `error.message`、`message`、`detail` 这类字段。网页、纯文本等非 JSON 返回仍只显示状态说明。
- 显示前会遮住本次请求用的密钥，以及 `sk-…`、`Bearer …`、`AIza…`、`api_key=…` 这类形状的字符串；去掉控制字符，最多显示 200 字。
- 流式回复中途出错时，提示“AI 服务在返回译文途中报错”，同样附上服务商原话。
- “获取可用模型”和“测试连接”也会显示服务商原话。

### 长文分段并发翻译

不带图片、超过 4,000 字的文字会拆成多段，最多同时发 3 个请求，完成后按原顺序拼回。拆分后不容易撞上单次输出上限（Claude 接口原先固定 8,192 个输出 token），也不容易超时。

- 专业模式和截图识字按段落块分组，同一块永远不拆开；每组按编号单独校验数字、表格列数和空单元格，再统一重新编号。
- 普通文字依次在空行、换行、句末处切分，每段约 3,000 字以内。英文句子之间原有的空格会保留。
- 4,000 字以内的文字、识图模式和单段重译仍是一次请求，行为不变。
- 任何一段失败，整次翻译都按失败处理，不会交出缺段的译文。

### 中文、日语目标的输出语言校验

1.1.1 起只校验英语目标。现在增加两种情况：

- **目标是日语**：长回复里几乎没有假名（低于 8%），又出现 4 个以上只在简体中文里用的字（这、们、说、发、关……），判定为返回了中文。
- **目标是中文**：假名 60 个以上，且占汉字加假名的 25% 以上，判定为返回了日文。中文里夹几个片假名作品名不受影响。

识图模式的画面说明可能引用原文，不做这两项校验。

### 思考强度

“设置 → API 设置”新增“思考强度”，每个服务商单独保存，选项为自动、关闭、低、中、高。

- **自动**：沿用 1.3.0 的做法，不新增任何字段；之前的翻译缓存继续有效。
- 其他档位按服务商各自的格式发送：
  - OpenAI 的 Responses 接口用 `reasoning.effort`，Chat 接口用 `reasoning_effort`。
  - DeepSeek 用 `thinking` 加强度字段。
  - Gemini 用 `reasoning_effort`；无法完全关闭思考的模型，“关闭”改用 `minimal`。
  - 通义千问只提供“关闭”（`enable_thinking: false`），因为它的思考模式需要流式输出。
- Claude 按模型分别处理：
  - Haiku 4.5 等旧模型用固定思考预算（1,024 / 4,096 / 8,192 tokens），输出上限相应加大。
  - Sonnet 5.5 等新模型用自适应思考加 `effort`。
  - 关闭思考时：Sonnet 5.5 用 `between_tools`；Opus 5.5 等无法关闭的模型改用最低强度；其他模型发送 `disabled`。
- 档位不被模型支持时，服务商会拒绝请求，App 会显示服务商原话；改回“自动”即可。

### App 内流式显示

在 App 里翻译时，阅读页会一边接收一边显示译文，卡片上标明“正在接收译文，完成校验后替换为正式结果”。

- 专业模式返回的是编号 JSON，接收过程中只显示其中的译文，不显示 JSON 本身。
- 全部收完后，仍走原来的版面、数字、语言校验，通过后才替换成正式结果、写入历史和缓存。校验失败按失败处理，不会把接收中的文字当作结果保存。
- 长文分段时，各段同时接收，按原顺序显示。
- 快捷指令不使用流式，仍等全文校验完成后再交付。
- 服务商忽略流式参数、直接返回完整 JSON 时，自动按普通回复处理。

### 版本号集中管理

版本号统一写在 `Scripts/generate_project.py`，测试包也带上同一版本号。界面测试改为读取测试包里的版本号，打包脚本也改为读取生成脚本里的版本号，升级版本时不用再改这两处。
