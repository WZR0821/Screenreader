# 后续开发方向

建议优先级是：先形成可重复的真机质量验收，再扩展识字与语义排版，随后优化本机快速翻译和等待时间。暂缓原图位置覆盖和复杂动画，以免分散对完整性与阅读体验的投入。

## 第一优先：真机质量闭环

用当前 1.0.0 在实机复测八张日英图片与实际菜单、通知、网页、票据；覆盖快速 / 专业 / 识图，日语译英、日语译中、英语译中及中英日目标切换。模型比较固定图片、提示词和配置，首次请求与缓存命中分开统计。

建立像素核对后的标注集，分别记录 OCR 覆盖率、阅读顺序、关键事实保留、语句质量和端到端延迟 P50 / P95。价格、数量、日期、否定与退款条件必须逐项核对；“请求成功”不能当作“翻译准确”。为不确定文字、截断、取消和重签名后的快捷指令连接准备验收案例。

对 Quick Look 工具栏隐藏记录 iOS 版本、触发步骤和恢复条件，做版本 / 设备矩阵。明确系统行为与 App 错误的边界，不承诺能够控制系统关闭控件。完成后才发布准确率和速度数字。

## 第二优先：识字与专业阅读

继续坚持按位置和邻近文字判断数字、表情与符号，不全局删除。扩充竖排日语、多栏、斜拍、艺术字、极小税费字、旧价删除线和复杂表格的回归素材。

局部重识别按不确定程度、关键事实与预算排序；让用户看到不确定区域并便捷修正。维护用户术语 / 品牌读法，避免把长音符、中点、※和金额符号当噪声。价格与商品、税费与金额、选项与必选提示等关系优先于像素级重建。

专业排版继续改进多列行归属、表头、促销价 / 原价、小字脚注和长段落；以最后一行可见、结构不串位、窄屏大字号不溢出作为验收条件。复杂布局应保守保留内容，无法确认关系时不擅自移除。

## 第三优先：本机快速翻译与效率

先测量图片处理、OCR、局部复核、网络等待和展示的分段耗时，优先优化实测瓶颈。快速模式控制处理预算但不牺牲关键字段；专业与识图保留完整性校验，不用漏内容换速度。

真机完善 Apple Translation 的语言包准备、下载状态、离线可用性、取消与前台生命周期。后台 Intent 仍走 API，不能把当前前台系统接口宣传成操作按钮后台离线引擎。若研究自带离线模型，先评估体积、内存、电量、许可和中英日质量再决定。

保留精确缓存键与提示词版本，先测跨场景命中率再考虑持久缓存。持久化若实施应可选、受保护、有 TTL 和一键清理；图片缓存需单独考虑隐私。App 内流式显示可后续研究，但“部分输出”与“完整结果”必须区分，系统全文文稿仍应在校验完成后交付。

## 识图专项

增强像素事实约束与同图裁剪选择，重点检查场景与文字分开、关键信息未漏、不可读文字不猜。比较视觉模型时检查实际图片能力与 token / 费用；模型路由或降级要明确告知，不能暗中增加上传或付费重试。

建立照片、海报、菜单和票据不同的评测目标，避免把画面说明做成冗长逐字重复。日语条件、时限与税费在识图大意中同样保留。

## 发布与长期维护

准备开发签名与 TestFlight 小范围测试，完善可访问性、VoiceOver、动态字体与深色模式；根据实际数据处理完成发布说明与平台申报。服务模型列表会变化，保留手动模型和自定义端点，逐次验证协议兼容。

可增加用户主动导出的匿名诊断，仅含阶段耗时、错误类别和配置能力，不包含 API Key、原文或截图。原图文字覆盖与自有阅读器可后续研究，但 iOS 对跨 App 交互和覆盖层有限制，需要明确产品入口与返回行为后再做。

本路线是后续计划，不是本版已实现功能。当前发布版本保持 1.0.0（17）；后续版本另行规划。
