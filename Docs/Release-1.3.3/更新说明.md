# 读屏 1.3.3（31）

日期：2026-11-14。开发者：Jerry Wong。最低 iOS 18.0。

本版做了三件事：

1. 截图翻译默认只出文字。“原图直译”改成一个开关，默认关闭。
2. 快速模式提速。
3. 重做原图直译的排版，减轻错位。

直接覆盖安装即可，原有设置都会保留。升级后原图直译是关着的，想用的话到 **设置 → 翻译偏好 → 模式与识字 → 原图直译** 打开。

## 截图翻译默认出文字

1.3.0 起，快速模式和专业模式翻译截图后，结果页默认显示原图直译，也就是把译文贴在截图上。现在默认只显示文字译文，和 1.3.0 之前一样。

- 原图直译放在 **翻译偏好 → 模式与识字**，默认关闭。
- 打开以后从下一次翻译截图开始生效。已经出来的纯文字结果不会自己变，因为它没有记下每段文字在截图上的位置。这时回到翻译页，主按钮会从“查看译文”变回“翻译”，点一下就用已经识别好的文字和位置把同一张截图重新翻译一次，出来的就是原图直译。这一下会再发一次请求，不点就不发。
- 操作按钮（快捷指令）也一样：开关关着时，全文窗口里只有文字；打开以后才带原图直译。

### 原图直译费不费 token

- 把译文画到截图上是在手机上做的，不另外发请求，也不花 token。
- 花 token 的是另一件事。为了知道每段译文该放在哪里，1.3.0 起快速模式会把识别出的文字按编号分块发出去，要求模型按块写回 JSON。分块格式的说明、每块外面的 JSON，以及模型写回的 JSON 都要算 token，回复变长，出结果也更慢。
- 拿测试里一张 8 行的菜单截图量过：纯文字发送 140 个字符，分块发送 1831 个字符，多出来的是格式说明和 JSON；回复 75 个字符对 225 个字符。
- 1.3.3 起，原图直译关着时，快速模式按纯文字发送，回到 1.3.0 之前的做法。
- 专业模式要靠分块保留段落、列表和价格的对应关系，所以照旧分块发送，用量不变，只是结果页不再默认显示原图直译。

## 快速模式提速

快速模式本来就是救急用的，这一版从三处省时间：

- **纯文字请求**：原图直译关着时请求和回复都更短，见上一节。
- **提前连线**：识别截图文字的同时，读屏先和 AI 服务建好连接，文字一识别完就发翻译请求，不用再等连接。提前连线只发一个空的 HEAD 请求，不带 API Key，也不带任何内容。
- **少思考**：思考强度是“自动”的时候，快速模式把几类默认会深度思考的模型调浅：
  - Claude 5 系列（Opus 5.5、Sonnet 5.5、Haiku 5.5，以及 Fable、Mythos）用最低的 low。思考没有关掉，Anthropic 也建议这样做，而不是直接关闭思考。
  - Gemini 2.5 Flash 和 Flash-Lite 关闭思考；Gemini 3 以后的 Flash 用最低的 minimal。Pro 型号降不到这么低，保持默认。
  - DeepSeek 和 ChatGPT 原有的快速设置不变。
  - 专业模式、识图模式，以及手动选了思考强度的模型都不受影响。

这些改动都是按各家文档做的，没有用真实密钥计时，所以实际快了多少还不知道。

## 原图直译的错位

以前的原图直译有两个问题，看起来就是错位：

- 字号按整块区域能放下的最大字号来定。译文比原文短时字会变大；多行段落的译文按自己的行距排，和原文的行对不上。
- 译文底下是一块白底（深色模式是黑底）色块，边距固定 2 点。截图背景不是白色时，每一块的边缘都很显眼。

现在改成下面这样，App 里的结果页和快捷指令的全文窗口用同一套排法：

- **字号**：识字时记下原文一行有多高、一块里有几行。译文字号不超过原文行高的 85%，看起来和原文差不多大或略小；译文短也不会放大。
- **行位**：原文有几行、行距多大，译文就一行一行落在原文对应的行上。
- **对齐**：居中的单行（标题、按钮）译文也居中；贴着右边的单行（价格、数值）靠右对齐。其余的靠左。
- **边距**：色块比原文多出的一圈随字号变化，是行高的 12%，最少 1.5 点，最多 5 点。
- **颜色**：色块用截图里原文周围的背景色，译文用原文的文字颜色，深色界面和彩色按钮上也一样。原文颜色太浅看不清时，读屏会把字加深或提亮到看得清。
- **放不下的时候**：先在原文的行位上把字缩小，最多缩到上面那个上限的 70%。还放不下，就用更小的字、更紧的行距排在原文区域里；只有一行的上下居中。
- **全文窗口的折行**：快捷指令全文窗口里的原图直译照搬 App 排好的行，每一行单独放在原文对应的行上，不再让网页自己折行。放不下的部分也不再在色块底边露出半截字，只在右下角用“…”标出，点按色块可以看全文。网页排版会把行高舍成整数像素，自己折行时每往下一行就往上偏一点，段落越长偏得越多（见“验证与交付”）。日文带注音和竖排的块行高不固定，仍由网页自己排。
- **提示词**：要求模型每块只译自己那一块。一句话跨到下一块时，在对应的位置断开，不把词、短语或数字挪到相邻的块里。提示词版本因此更新了，升级后第一次翻译同一张截图不会用到旧的缓存。这条规则让每次分块请求多了约 300 个字符（上面的 1831 里已经算上），只在专业模式和打开原图直译时才发。

1.3.3 之前保存的翻译记录没有行高信息。重新打开这些记录时，读屏按区域大小估算行高，最多按 32 点算。

### 还没解决的

- 在 Mac 上用 CoreText 量过：行距固定时，中文字形基本落在每一行的正中，偏差不超过字号的 3%；拉丁字母偏下约字号的 7%。所以译成英文时，每行字会比原文略低一点，17 点的字大约低 1 点。
- 原图直译的位置全靠本机识字（Vision）给的框。识字把两行并成一块、或者框本身偏了，译文也会跟着偏。
- 译文比原文短、排不满原文的行数时，从原文第一行排起，下面的行只剩背景色。测试截图里原文两行“Freshly made every morning. / Served until noon.”，译文“每天早上新鲜制作。 供应至中午。”一行就放下了，第二行空着。
- 快捷指令全文窗口的画面比 360 点窄时，网页里的英文字会比 App 排的略宽一点，个别行尾会伸进色块的边距，最多被色块边缘切掉一点。画面比 360 点宽时字是放大的，按系统字体的排法只会排得更紧，但没有实测过。
- 模拟器截图里，App 内原图直译的色块上边和右边常有一条约 1 像素的浅灰细线。1.3.2 同一测试的截图在同样位置也有，不是这一版带来的。原因还没查，真机上有没有也还没看过。

- **核心检查** `swift test`：216 项，全部通过。比 1.3.2 多 14 项，都在 `Release133Tests.swift`：
  - 原图直译默认关闭，保存后保留。
  - 快速模式里 Claude 5 系列只在思考强度为“自动”时降到 low；Gemini Flash 各型号的最低档；Pro 型号、专业模式和自定义服务不受影响。

  - 行高信息在翻译记录和译文核对之后仍然保留。

- **回归中发现、已经改好的应用问题**：
  - **打开开关后，已经翻好的截图看不到原图直译**（界面测试发现）。翻译页的主按钮原来还是“查看译文”，点了只会重新打开纯文字结果。现在主按钮会变回“翻译”，见“截图翻译默认出文字”一节。新增的集成测试核对了三件事：这时只多发一次分块请求；翻完以后按钮又是“查看译文”，不会再发；识别出的文字改过以后不走这条路，按原来的方式翻译。
  - **快捷指令全文窗口里的段落越往下越往上偏**（iOS 测试发现）。网页把行高舍成整数像素，测试页上每行少约 0.9 点。改成每行单独定位，见“全文窗口的折行”。
  - **全文窗口里的“…”比译文大**（看截图发现）。字号挪到译文本身以后，表示后面还有字的“…”没有跟着改，用的是网页正文的字号，在小色块上会把前面的字盖掉一截。已改回和译文一样大，加了一项测试。
- **另外 3 项失败不是应用的问题，应用没有为它们改动**：
  - `ShortcutsSystemTests` 1 项：测试还按旧的默认值，以为全文窗口一打开就是原图直译。1.3.3 默认只出文字，第一轮的截图里确实只有文字。改成测试启动时打开原图直译。
