# 读屏 1.0.0 开发总结

> [!IMPORTANT]
> **本 APP 由 GPT-6Astra 开发完成。**

本阶段完成面向 iPhone 的识屏翻译应用，版本 1.0.0（构建 17）。核心目标是把提供的截图完整读出来，以所选语言翻译，并在可滚动的系统全文窗口中阅读。本文按最终产品能力描述一次完整交付，不按中间版本排列。

## 输入、语言与工作流

支持输入 / 粘贴文字、照片和文件图片。来源可自动识别或指定中文、英语、日语，目标可选三语；日英混排不会简单归为陌生语言。语言选择同时影响 Vision OCR 与翻译指令，自定义要求中的语言变量也随之更新。新设置默认自动来源、英语目标、DeepSeek / deepseek-flash，已有明确偏好继续保留。

操作按钮通过已签名的三步快捷指令连接“截屏 → 翻译截图全文 → 快速查看”。App 内提供安装入口、绑定按钮步骤和排错说明。正式入口返回全文文件；兼容预览动作保持原标识与返回类型但隐藏，避免误选短预览。文字翻译 Intent 继续可用。

## 三种模式与提示词

快速模式使用精简 API 指令和较小的 OCR 处理预算，要求完整、简洁，保留关键数字、否定和条件。App 内可选择 Apple 系统翻译；选系统服务时只开放快速模式。系统路径不读取 API Key，不应用模型提示词，失败不自动切到收费 API。操作按钮继续使用 API。

专业模式先在本机确定源文的顺序与类型，再把带 ID 的内容块交给模型翻译。标题、列表、正文、标签与值、表格列的归属由本机恢复。每个 ID 必须恰好出现一次，内容不可为空，数字和列关系必须符合原文；模型新编造的类型不会控制界面。异常不自动降级、不伪装成功。

识图模式将全图和最多两张同图细节裁剪放入一次请求；本机 OCR 仅作为可能出错的参考。按所选目标语言分别讲解“文字大意”和“画面大意”，保留主要金额、时间、限制和条件，画面描述避免重复翻译文字，无法辨认的内容明确说明，不猜不可见细节。需使用实际支持图片的模型。

每个模式有独立默认规则及自定义要求，可分别编辑、保存、重置。支持 `{source_language}`、`{target_language}`、`{tone}`、`{glossary}` 四个变量。目标语言、输入作为数据和专业输出结构优先于附加要求；旧全局提示词可迁移到三个模式。

## 识字与信息关系

- 使用 Apple Vision accurate OCR。快速普通图长边上限 2560，专业 4096；长图采用更高的适配分辨率与重叠切片，去除切片重复，避免直接丢弃下半截。
- 过滤依赖几何位置与上下文：状态栏需同时有时间和右侧状态证据；数量旁加减控件、导航符号、孤立标点和细分隔线分别判断。数量、价格、日期、负数、评分、有效表情及数学符号不会因为单独出现而统一删除。
- 模糊、小字、漏掉的字段可局部放大再次识别；专业一般复核最多八个区域，快速跳过一般复核但允许一个缺失数字字段复核。日期、文字脚本、货币字形的修正需满足对应像素读数与上下文约束，不从数字串凭空推断日期，不随意删除价格尾数。
- 保持阅读顺序、商品与邻近价格、双语副标题、数量与库存的独立归属，以及多列表格的行列关系。原始 OCR 文字保留用于核对；不确定结果可主动用识图模式重试，不会偷偷上传图片。

## 字符与排版

标题判定同时参考字符大小及识别框高度，邮箱、孤立符号、高表情和日期不应被当成大标题。正文跨行可重连；项目、邮件字段、税费脚注和不同语言署名保持有意义的边界。

统一换行与多余空行，清理控制字符，同时保留表情中的连接符、肤色和变体。处理标点前多余空格、跨行括号与无意义的整段 Markdown 包装；不会全局删除星号、井号、长音符或中点。小数和日期不被误当作编号，编号与语义警告 / 勾选标记不重复添加圆点。

App 与全文 HTML 使用相同的结构化结果。阅读器保留全部内容、可滚动到最后一段；原文通过“查看原文”展开或收起。内联 CSS 支持主题、字号和间距，所有文字转义，不执行模型 HTML，不加载脚本或远程字体。

## 日语专项

默认指令对日语假名与长音符、外来词、人名和品牌采用谨慎处理。重点保留含税 / 未税、以上 / 以下与未满 / 超过的边界、起始与截止时间、外带 / 堂食、额外收费、每人限制、套餐 / 单品、必选、不可叠加和 ※ 脚注。

菜单的“去除任意一种配料时不提供整份酱汁”、退款的“未使用且至少提前 72 小时”、交通票种限制、日期修订等条件应整体翻译，不省略否定或把 AND 改成 OR。App 界面为中文，示例以英语为主，日语优化主要体现在底层识别与指令中。

## API、效率与持久化

支持 DeepSeek、OpenAI、Gemini、Claude、通义千问和自定义 HTTPS 端点；三种协议为 Chat Completions、Responses、Claude Messages。预设模型可选，也可获取列表或手动填写，实际能力由账户与服务决定。各服务商的地址、模型与密钥隔离；凭据存 device-only Keychain。

文字缓存只在内存中保留，20 分钟有效，最多 40 条、约 1 MB。匹配包含源文、块关系、语言、模式、当前模式提示词、术语、服务配置和密钥指纹；改变外观不重新翻译，改变另一个模式提示词不影响当前有效命中。失败、不完整响应与识图解释不缓存。不增加自动付费重试。

历史记录保存原文和译文等文字结果，不保存截图；可选 10 / 30 / 100 条、搜索、逐条删除或清空。关闭保存并确认保存后清空既有记录。原子写入、UUID 去重、旧记录迁移与损坏文件保护已实现；取消后不会显示迟到的旧结果，编辑原文会清除失效译文。

## 界面、品牌与兼容

应用中文名读屏、英文名 Screenreader，开发者 WANG ZIRUI，使用重新设计的图标和石板蓝 / 象牙白基调。提供深浅主题、五组强调色和自定义颜色，字号、行距及原文默认展开状态可设置。

翻译页突出语言、模式、输入和结果；交换语言增加轻量动效与触感，遵循减少动态效果设置，不增加请求等待。测试用模拟按钮不进入 Release。设置首页按“翻译、API 设置、模式提示词、外观与阅读、缓存与记录、操作按钮、使用说明”组织；常规竖屏一屏展示，大字体或短屏允许滚动以保持可访问性。

内部工程名、Bundle ID、偏好键、Keychain service 和 Intent 标识保持兼容。旧“屏译全文”无需仅因改名重建；重签名若改变应用身份需重新连接已安装版本的动作，并保持原钥匙串权限。

## 当前边界

产品具备完整流程与回归测试，但构建 17 尚未重新进行真机在线 API 验收。系统 Quick Look 的工具栏、应用推荐和高度不由 App 控制，不能宣称已修复系统级按钮隐藏或实现半屏覆盖。识别范围仅限传入截图，复杂竖排、模糊艺术字和屏外内容仍有局限。
