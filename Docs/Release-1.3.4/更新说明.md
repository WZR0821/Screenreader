# 读屏 1.3.4（32）

日期：2026-11-20。开发者：Jerry Wong。最低 iOS 18.0。

本版做了一件事：加了“语言优先级”。

原文语言选“自动识别”、输入的内容又已经是目标语言时，读屏不再把它“翻译”成同一种语言，而是按优先顺序改译成另一种语言。默认顺序是 中文 › 日语 › 英语，所以目标语言是中文时，输入中文会译成日语。

直接覆盖安装即可，原有设置都会保留。这个功能升级后默认是开着的；不想用，到 **设置 → 翻译偏好 → 语言优先级** 关掉“自动改译”，就和 1.3.3 完全一样。

## 语言优先级

### 规则

只有一条：**原文语言是“自动识别”，并且读屏判断出输入的内容就是所选的目标语言时，改译成优先顺序里排在最前的另一种语言。** 其余情况都按所选的目标语言翻译。

按默认顺序 中文 › 日语 › 英语：

| 所选目标语言 | 输入的内容 | 实际译为 |
|---|---|---|
| 中文 | 中文 | 日语 |
| 中文 | 日语、英语 | 中文（不变） |
| 日语 | 日语 | 中文 |
| 英语 | 英语 | 中文 |

把顺序改成 中文 › 英语 › 日语，输入中文就译成英语。

- 所选的目标语言不会被改掉。只有这一次翻译换了方向，设置里和下一次打开翻译页时，还是你选的那个。
- 原文语言是手动选的（中文、英语或日语）时不改译。手动选了就按你选的来。
- 识图模式不改译：它是用目标语言解释一张图片。
- 在结果里“核对”并重译某一段时不改译，这一段和整篇结果保持同一种语言。
- App 内的系统翻译和 API 翻译用同一条规则。

### 在哪里设置

**设置 → 翻译偏好 → 语言与表达 → 语言优先级**。这一行右边显示当前的顺序，关着时显示“关闭”。里面有三组：

- **自动改译**：总开关，默认打开。
- **优先顺序**：按住右侧的三条横线拖动。
- **当前效果**：按现在的顺序列出“原文和目标都是中文／日语／英语”时各译为什么，改完顺序马上能看到。

### 翻译页怎么提示

输入框里的内容会被改译时，翻译页在发送之前就显示出来：

- 语言栏左边从“原文语言 自动识别”变成“自动识别到 中文”，右边从“译为 中文”变成“按优先级译为 日语”，两处小字换成强调色。语言栏高度不变，翻译页仍然刚好一屏。
- 点开目标语言菜单，标题写着“原文已是中文，按语言优先级译为日语”；菜单里打勾的还是你选的语言。
- 这一次就想译成所选的语言，把原文语言从“自动识别”改成具体的语言即可。

### 结果里的说明

改译的结果上方有一行小字：“原文是中文，已按语言优先级改译为日语。”“翻译信息”里目标语言下面也有同一句。翻译记录会记下这句话，以后翻出来也知道当时为什么译成了日语。

### 截图、照片和快捷指令

截图和照片识别出的文字、“翻译文字”快捷指令传进来的文字，也在自动识别时判断，但判得更严：**整段文字从头到尾都是目标语言才改译，里面只要有别的语言的句子，就照常译成所选的目标语言。**

这样做是因为截图和键盘输入不一样：

- 截图里混着手机自己的界面文字和真正想看的内容。一张中文聊天截图里有一句日语，截图多半就是为了看懂那一句。按整屏“中文居多”来判断，会把整张图译成日语，那一句日语反而原样留着。
- 长按操作按钮没有预览，结果出来之前看不到会译成什么。

目标语言是中文时的界限：

| 截图里的文字 | 结果 |
|---|---|
| 全是中文（设置页、中文文章、中文通知） | 改译为日语 |
| 中文里夹着产品名（App Store、iPhone 16 Pro Max） | 改译为日语 |
| 中文里有一句日语（两个以上假名） | 译为中文 |
| 中文里有一句英语（一行里连着四个以上英文单词） | 译为中文 |
| 英文字母比较多（单词表、中英对照） | 译为中文 |
| 有一行韩文、俄文等其他文字 | 译为中文 |
| 只有中日文写法一样的汉字（“定休日”） | 译为中文 |

改译的结果在这几处都写明原因：App 里的结果上方、快捷指令全文窗口的顶部、快捷指令的结果卡片。

只有汉字、而且这些汉字中日文写法一样的内容，键盘输入和截图的处理不同。键盘输入或粘贴的，按优先顺序里中文和日语谁排在前面算，默认是中文，于是改译成日语。截图和快捷指令来的分不出是哪种语言，不改译。

## 怎么判断原文是什么语言

判断在手机上完成，不发请求，不花 token。翻译页每次按键都会重新判断一次。

- **先数字符**：假名、汉字、拉丁字母和其他文字各有多少。韩文、俄文、阿拉伯文等占比高的不判断。汉字假名和拉丁字母混在一起的（“What does 你好 mean?”“帮我翻译 hello world”）也不判断：中文里带几个英文词（“这个 bug 怎么修”）仍算中文，英文再多就当作是要翻译的内容。
- **英语**：基本都是拉丁字母的算英语。满 20 个字母时再用系统的语言识别核对一次，法语、德语、西班牙语不会被当成英语。否则选了“译为英语”时，它们反而会被改译成别的语言。
- **中文和日语靠用字区分**：
  - 有假名，或者有日语才用的字形（駅、円、図、楽、気），是日语的证据。
  - 有中文才用的字（这、们、说、你、很、哪），是中文的证据。
  - 两边证据都有、多的一边没有超过另一边两倍的（中日文混排），不判断。
  - 繁体中文不改译。读屏的“中文”目标是简体中文，把繁体内容译成简体是有用的。
  - “東京都”“日本語”这样只有繁体字形的，可能是日语也可能是繁体中文，不判断；“国語学習”“会議室”这样同时有简体中文没有的字形和繁体中文没有的字形的，只能是日语。
- **字表**：按三套国家标准的常用字算出来，GB 2312 一级 3755 字、Big5 常用字 5401 字、JIS X 0208 第一水准 2965 字。按“中文常用而日语不用”“日语有而中文两种写法都没有”等分成六张互不重叠的表，共 5327 字。生成脚本是 `Scripts/generate_language_tables.py`，可以重跑核对。
- **截图、照片和快捷指令从严**：上面每一条的界限都收紧，见“截图、照片和快捷指令”一节。
- 很长的文字只看前 4000 个字符。

判断不出来就不改译，按所选的目标语言翻译，和以前一样。

### 例子

目标语言是中文、顺序是默认的 中文 › 日语 › 英语 时。这些例子都在核心检查里：

| 输入 | 判断 | 结果 |
|---|---|---|
| 这个东西多少钱？ | 中文 | 改译为日语 |
| 帮我看看这个 bug 怎么修 | 中文 | 改译为日语 |
| Good morning. | 英语 | 译为中文 |
| 今日は天気がいいですね。 | 日语 | 译为中文 |
| 営業中 | 日语 | 译为中文 |
| 定休日（键盘输入） | 分不出，按顺序算中文 | 改译为日语 |
| 定休日（截图里的） | 分不出 | 译为中文 |
| 東京都 | 分不出 | 译为中文 |
| 這個東西多少錢？ | 繁体中文 | 译为中文 |
| 这个东西多少钱？これはいくらですか。 | 中日混排 | 译为中文 |
| What does 你好 mean? | 中英混排 | 译为中文 |
| 帮我翻译 hello world | 中英混排 | 译为中文 |

## 参考了哪些翻译软件

做之前看了几款翻译软件怎么处理“原文已经是目标语言”：

- **Easydict**（[Raycast 版说明](https://github.com/tisfeng/Raycast-Easydict/blob/main/README_ZH.md)）：设“偏好语言”，默认是简体中文和英文。输入的内容译成第一种偏好语言；自动识别出的语言和第一种偏好语言相同时，改译成第二种。识别拿不准时也按偏好语言的顺序优先，文档里的例子是英语单词 heel 被别的服务认成荷兰语。
- **Raycast**（[官方指南](https://www.raycast.com/guides/how-to-translate-text-on-mac)）：自带的翻译只有原文语言和目标语言，原文语言默认自动检测，不会自己换方向。它的 Google Translate 扩展有“主要语言”和“次要语言”：译成主要语言，选中的文字已经是主要语言时改译成次要语言。
- **Pot**（[界面文字](https://github.com/pot-app/pot-desktop/blob/master/src/i18n/locales/zh_CN.json)）：翻译设置里有“目标语言”和“第二目标语言”两项。只看到了界面文字，没有找到写明规则的文档。
- **DeepL API**（[接口文档](https://developers.deepl.com/api-reference/translate)）：目标语言由调用方指定，文档里没有自动换方向的说明，要应用自己处理。

读屏的做法和 Easydict、Raycast 的 Google Translate 扩展是一个思路，按自己的情况改了几处：

- 三种语言排成一个顺序，而不是只设两个。目标是日语或英语时也有地方可去。
- 保留原有的“原文语言／目标语言”两个选择，只在“自动识别”时才改译，手动选的不动。
- 发送前在翻译页显示会译成什么，结果上再写明原因。
- 判断全部在本机完成，分不出来就不改。
- 截图单独从严。上面几款软件的截图翻译是自己框选一块区域，读屏的操作按钮截的是整屏，界面文字和内容混在一起，不能只看哪种语言多。

## 还没解决的

- 键盘输入的日语词如果只有共用汉字（“山田”“学生”），默认顺序下会被当成中文，改译成日语。翻译页在发送前会显示“按优先级译为 日语”，不对的话把原文语言改成“日语”，或者把日语排到中文前面。
- 少于 20 个字母的拉丁字母内容一律当英语。目标是英语时，“Bonjour”这样的短词会被改译成优先顺序里的另一种语言。
- 很长的文字只看前 4000 个字符，后面换了语言不会察觉。
- 截图里的外文如果只有很短的一两个词（“Sign in”、一个假名），仍会被当成整张都是目标语言。
- 反过来，全中文的截图里有一长串网址或文件路径（连着四段以上英文字母）时，会被当成有英语句子，不改译，结果和 1.3.3 一样。
- 本机识字偶尔把汉字认成形近的假名（“口”和“ロ”、“力”和“カ”）。认错两个以上时，全中文的截图会被当成有日语，不改译，结果和 1.3.3 一样。
- 繁体中文不改译，也不能单独排进优先顺序。读屏的目标语言只有简体中文、日语、英语三种。
